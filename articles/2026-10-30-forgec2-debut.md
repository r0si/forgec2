## 先说结论

ForgeC2 是一个**自托管的 C2 框架**，以**单个二进制**交付：React 控制台、REST API、beacon 入口和 SQLite，全部跑在一个进程、一个端口上。当前版本 **2.7.1**，MIT 许可。

它有 223 个植入体任务、9 种传输、52 个可插拔插件、43 个控制台页面，以及一套把"发布"本身当作安全边界来设计的供应链。

但我想先讲清楚**它不承诺什么**，因为这决定了它适合谁。

---

## 一、起因：被"跑不起来"和"看不明白"磨出来的

我做这个东西，最直接的动机来自两件很朴素的事。

**第一件：工具装不起来。** 很多 C2 要 teamserver + 客户端 + 数据库 + 前端服务，四五样东西凑齐了才能开始。环境一换、账号一换、PATH 一短，就卡在"为什么起不来"。

**第二件：失败了不知道为什么。** 生成一个载荷，等了几分钟，回来一句 `Build failed`。是没装 Go？缓存不可写？代理不通？还是代码本身编译不过？没人告诉你。

所以我给自己定了两条硬要求，后来变成了这个项目的性格：

- **能一个文件跑起来，就别让人装第二个东西。**
- **任何一次失败，都必须说清楚"为什么"和"接下来做什么"。**

## 二、它是什么

一句话：**把一个 C2 该有的东西，压进一个进程里。**

```
运维人员 ──► ForgeC2（单二进制，单端口 :8000）
                │
                ├─ Web 控制台（React，内嵌）
                ├─ REST API（Gin + WebSocket + AI）
                ├─ Beacon 入口
                ├─ SQLite / 插件 / 脚本 / OPSEC 规则
                └─ 构建队列 ──► 交叉编译出的植入体
                                 │
               HTTP(S) / WSS / gRPC / mTLS / H2C / TCP / DNS / ICMP / SSH
                                 │
                    Windows / Linux / macOS 植入体（含 P2P）
```

没有单独的数据库进程，没有单独的前端服务器，没有需要 `docker compose` 拉起来的第三个容器。第一次启动会做三件事：生成 `config.yaml`、把随机生成的 `admin` 密码打印到控制台、在 `127.0.0.1:8000` 起一个自签名 HTTPS 控制台。

## 三、载荷工厂：能生成，比生成得快更重要

植入体覆盖 EXE / DLL / PowerShell / ELF / macOS，另有 XOR stager、shellcode、Donut 和一行命令，全部在服务端交叉编译完成。图标伪装、`jpg.exe` 双扩展名这类细节也做在里面。

但这一块我最近花时间最多的，**不是让它更快，而是让它更诚实**。

### 1. 构建之前先体检

新增了一个预检端点：在点下"生成"之前，先探测服务器进程自己能不能找到 `go`、缓存目录能不能写、植入体源码树在不在。环境不对就直接返回 400 和缺什么，**不再让你排几分钟队然后收到一句失败**。

这一点很关键：**你所在的 shell 里 `go` 能跑，不代表服务器那个服务账户能找到 `go`**。服务账户的 PATH 往往更短。这个坑我自己踩过。

### 2. 失败不再是一句空话

以前编译器报错会被一个"脱敏"函数替换成通用句子，于是界面上永远只有 `Build failed`。现在它保留编译器原话（口令与密钥形状的内容会被遮掉），并附一句能照着做的提示：

- 找不到工具链 → 提示检查服务账户 PATH
- 缓存不可写 → 提示换一个可写的 `GOCACHE`
- 磁盘满 → 直接点名
- 模块代理不通 → 提示检查 `GOPROXY`
- 模块清单缺项 → 提示 `go mod tidy`

前端会在失败信息下方单独渲染这张"提示卡片"。**排查成本从"猜"变成"读"。**

## 四、交接与复盘：C2 也得能交付

一个演练结束，真正难的不是打点，是**交接**：把这次做了什么、哪里没做完、哪些失败了，打包成一个别人能核对的东西。

`GET /api/engagements/{id}/bundle` 会生成一个 zip：摘要、时间线、任务表、审计 NDJSON、主机清单、凭据元数据、IOC、插件清单，以及一份带 SHA-256 的 `MANIFEST.json`。签名是可选项（Ed25519），没配密钥时它诚实地标记为"未签名"，而不是假装签过。

最近补的一处是**失败叙事**：Markdown 摘要里现在会按失败原因分组列一张表——

| 失败数 | 受影响主机 | 最忙主机 | 原因 |
|---|---|---|---|
| 3 | 1 | web-01 | connection refused |
| 1 | 1 | db-02 | access denied |

同一份计算也会写进 `failures.json`。**一次计算，两处呈现**，不会出现"报告和数据对不上"。

同理，结构化剧本（Playbook）的运行状态里，"等审批"和"等依赖"是两个不同的阻塞，会被分开命名——因为前者需要一个人去点，后者自己会解开。混成一个词，待办就会被忽略。

## 五、供应链：C2 自己就是高价值目标

这一点我想说得直白些：**C2 服务器被攻破的后果，比普通服务更严重。** 所以发布链路是按"可核对"而不是"可信任"来造的。

- **签名发布**：每个二进制与压缩包附带 `.sha256` 和独立的 Ed25519 `.sig`；打 tag 时缺少签名密钥会**失败关闭**，不会静默出一个未签名版本。
- **SBOM** 随发布附上。
- **可验证的热更新**：下载对应资产 → 校验和与签名 → 快照数据库 → 通过生成的 restarter 重启 → 结果写入 `.update/last`；起不来就**回滚到上一个二进制**；并发更新直接 409。
- **12 个 CI 任务**：格式化与 vet、golangci-lint（含 gosec）、govulncheck、gitleaks、race detector、fuzzing、C 植入体构建、Docker、API 冒烟、agent E2E、前端门禁、实机 E2E。
- **410 个 Go 测试文件 + 182 个前端测试文件**，外加 OpenAPI 契约检查、i18n 键覆盖、内嵌前端包的逐字节一致性检查。
- 本地还有 **31 道静态门禁**（对比度、无障碍、路由权限、错误脱敏、路径、命令分隔符、MITRE 覆盖等）。

这些数字不是为了好看。它们的作用是：**改错东西的时候，能立刻红。**

## 六、和同类工具比，我只比"打包与交付"

| | ForgeC2 | Sliver | Mythic | Havoc | Cobalt Strike |
|---|---|---|---|---|---|
| 打包方式 | 单二进制 + 内嵌 Web | 服务端 + CLI | Docker Compose | Teamserver + Qt | Java + 桌面客户端 |
| Web 控制台 | 内置 | 无 | 有 | 无（Qt） | 无（桌面） |
| 传输 | 9 种 + P2P | 4 种 | 依赖 C2 profile | 3 种 | 4 种 |
| 载荷构建 | 服务端交叉编译 | 服务端 Go 编译 | 每 agent 容器 | Teamserver | Artifact Kit |
| AI 助手 | 有 | 无 | 无 | 无 | 无 |
| 更新路径 | 签名、可回滚 | 手工替换 | `mythic-cli` 检查 | 手工 | 厂商更新 |
| 许可 | MIT | GPL-3.0 | BSD-3 | GPL-3.0 | 商业 |

**这张表只比较打包方式与交付链路，不比较战术与检出率。** 检出率取决于目标环境的 EDR、配置、流量画像，任何"我们更隐蔽"的横向比较都不可信。

## 七、怎么开始

三种方式，都不需要你先装一堆依赖。

**方式一：一键压缩包（不需要工具链）**

- Windows：解压 `forgec2-v2.7.1-windows-amd64.zip`，进目录运行 `start.cmd`
- Linux：`tar xzf forgec2-v2.7.1-linux-amd64.tar.gz && cd forgec2-v2.7.1-linux-amd64 && ./start.sh`

**方式二：Docker**

```bash
cp config.example.yaml config.yaml
docker compose up -d --build
```

**方式三：从源码构建**（Go 1.26+、Node.js 24.15+）

```bash
git clone https://github.com/r0si/forgec2.git && cd forgec2
powershell -File scripts/deploy.ps1 -NoStart   # Windows
bash scripts/deploy.sh --no-start              # Linux / macOS
```

> 如果你从**另一台机器**访问控制台：它默认监听 `0.0.0.0`，请把该主机名加进 `server.allowed_origins`，否则每个 API 调用都会被当成跨域拒掉。

## 八、边界：它只做授权测试

这一条必须放在正文里，而不是角落。

ForgeC2 是**授权安全测试**工具。在任何系统上使用它之前，你必须持有该系统所有者**明确的书面许可**。用于未授权的系统，在几乎所有司法辖区都是违法的。

我也尽量让工具本身不鼓励误用：控制台第一次启动就要求你改掉随机密码；危险任务可以要求双人审批；审计链是哈希链，导出时明确说明它能发现**部分篡改**、但**不能**发现"有写权限者重算全部哈希"——这条限制写在文档里，而不是留给人猜。

**能说清楚自己做不到什么，比宣称自己什么都能做更有用。**

## 九、接下来

这个项目还在早期。接下来我会继续沿三个方向做：

1. **可观测性**：让"为什么没成功"在更多地方一句话说清（构建、投递、任务、剧本）。
2. **可交接性**：让一次演练的产物能被第三方独立核对，而不只是自己看得懂。
3. **可验证的供应链**：让"这个二进制是不是我发布的"成为一个能算出来的问题。

如果你在做授权测试、红队演练或安全研究，欢迎试用、提 issue、指出我写错的地方。**这个项目里最贵的不是功能，是那些能被复现的判断。**
